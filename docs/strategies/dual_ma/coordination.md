# 雙均線任務協作與檔案所有權

## 任務拓樸

```text
雙均線交易系統｜00 研究與規則決策
├─ 雙均線交易系統｜01 選股與資料治理
├─ 雙均線交易系統｜02 回測與研究報告
└─ 雙均線交易系統｜03 監控與部署
```

## 權責

| 任務 | 主要責任 | 第一輪狀態 | 禁止自行處理 |
|---|---|---|---|
| 00 主控 | 規格、決策、派工、驗收、升版及合併 | `ACTIVE` | 不以執行方便為由跳過證據 |
| 01 選股 | 股票母體、候選名單、資料凍結與輸出契約 | `DATA_BUILD_IN_PROGRESS` | 不依績效改名單；不改交易規則 |
| 02 回測 | 因果成交、成本、績效比較與研究報告 | `ENGINE_READY_WAITING_FOR_DATA_ADAPTER` | 不自行最佳化規則；不接正式監控 |
| 03 監控 | 狀態機、持倉、Shadow、通知及恢復能力 | `WAITING_FOR_BACKTEST_ACCEPTANCE` | 不部署草稿；不改策略定義 |

## 建議檔案所有權

| 所有者 | 路徑 |
|---|---|
| 00 主控 | `docs/strategies/dual_ma/**`、未來的版本化策略契約 |
| 01 選股 | `stock_ai_bot/selection/**`、指定的掃描整合與選股測試 |
| 02 回測 | `backtests/dual_ma/**`、指定的回測測試與 reference runs |
| 03 監控 | `trade_monitor/strategies/dual_ma/**`、監控及 Shadow 測試 |

跨越所有權範圍的修改必須先回報主控。現有大型檔案如 `stock_ai_bot/scanning/technical_scanner.py` 若確實需要修改，必須先說明原因、影響範圍與替代方案。

## 分支與 worktree 規則

1. 三個執行任務都以同一個已更新 `main` commit 為基準。
2. 第一輪唯讀盤點不建立分支、不修改檔案。
3. 需要保存變更時才建立 `codex/dual-ma-<area>-<version>` 短期分支。
4. 一個分支對應一組可獨立測試、審核及合併的變更；不是每次對話或每次回測都建分支。
5. 合併順序原則：共用規格／契約、選股、回測、監控。
6. 合併後在 `main` 重跑相關測試，再刪除已合併分支。
7. 同一角色可重用原 worktree；開始下一輪前必須更新到最新 `main` 並確認工作區乾淨。

## 共享資料與輸出

- Git 只保存規格、程式、測試、小型 fixture 及經採納的精簡結果。
- `data/`、`reports/`、`outputs/`、資料庫、密鑰及實際帳戶設定不提交 Git。
- 多個 worktree 使用同一份唯讀行情來源；每次輸出使用唯一 `run_id`，不得共寫同一檔名。
- 正式參考回測經主控採納後，才提升至 `backtests/dual_ma/reference_runs/<run_id>/`。

## 第一輪交付順序

1. 00 已將單次實驗契約凍結為 `v0.4.1-frozen`。
2. 01 建立股票母體、歷史選股資料、資料快照及輸出契約。
3. 02 可與第 2 步並行完成因果回測引擎、輸入驗證、run manifest 與測試。
4. 01 交付後，由 00 驗收資料契約，再讓 02 加入資料 adapter；不得反向修改母體以改善績效。
5. 02 執行六組矩陣、成本與滑價敏感度，產出逐筆帳本與可重現報告，由 00 判讀。
6. 只有主控採納回測候選版本後，03 才開始 Shadow 接入；不得直接正式下單。
