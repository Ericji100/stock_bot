# 定錨與動態象限整合 RC

## 目的

`enlightenment-integrated-v1.7-anchor-rc-shadow` 將課程中的定錨、反向定錨、大小級控制權及象限演化，嵌入既有的單一監控狀態機。它不建立另一套平行答案，也不新增第五種進場型態；最後仍由原有四型態、交易憲法、結構停損與九欄通知共同決策。

正式 `v1.6-dual-scale` 維持 schema v4／market structure state v2。RC 明確指定 schema v5／state v3 才會載入 `anchor_context`，因此不會因模組更新而讓正式流程暗中改用新規則。

## 因果流程

每輪只能使用最新已收盤 K 與更早資料，依序更新：

1. 建立或延伸定錨候選，但不得回填先前未曾辨識的 `first_seen_at`。
2. 在破壞證據完成後，把候選由 `FORMING` 轉為 `CONFIRMED`。
3. 同時保存大級與小級錨；小級反向錨不會自動抹掉尚未失效的大級錨。
4. 判定目前由大級、小級或未定義級數掌握控制權。
5. 依錨後的趨勢性與波動性，給出唯一工作象限，以及最多一個次要候選；沒有足夠證據時維持 `TRANSITION` 或 `UNDEFINED`。
6. 象限只控制既有四型態的准入與管理，不獨立產生交易訊號。

錨的狀態只可依 `FORMING → CONFIRMED／INVALIDATED／REPLACED` 的合法生命週期前進。正式失效或被替換後不得改寫歷史內容。同一 session 的錨也不得無故消失。

## 大小級與象限

- 大小級同向：優先以大級情境說明方向，小級負責較近的觸發與停損結構。
- 大小級衝突：明說目前由哪個級數掌握控制權；大級防線未破前，不得把小級反向走勢直接宣告為大趨勢翻向。
- Q1：趨勢與波動同時提高，既有突破或延續型態可優先，但仍禁止追價。
- Q2：趨勢低、波動高，普通壓縮突破不可用；慢速外擴失敗只能作為既有假突破／假跌破型態的一個分支。
- Q3：趨勢與波動皆低，只在合格箱型邊界評估既有突破或反轉型態，中央禁止交易。
- Q4：趨勢高、波動低，既有趨勢拉回延續優先，等待回測與重新發動，不在遠離結構處追價。

## 九欄通知如何呈現

- **大趨勢**：說明大級錨的方向、起訖段、確認或失效依據。
- **當前趨勢**：說明小級錨、目前控制級數，以及大小級是否一致。
- **市場狀態**：只給一個工作象限；必要時列主、次候選及已排除象限，說明趨勢／波動正在增加或減少。
- **尚缺條件／觸發**：分別列出延續路徑與反向定錨路徑，並明確指出哪一根已收盤 K 或哪個結構事件會改變象限看法。

例如：

> 大級多方錨仍有效；小級空方反向錨正在形成，小級暫時掌握控制權。工作狀態為轉換中，主候選 Q2、次候選 Q4。若小級空方錨無法破壞大級多方防線並重新站回壓力區，轉回 Q4 的趨勢拉回情境；若已收盤 K 有效破壞大級防線且新方向延續，才確認大級反向定錨並重判象限。

點位只有在圖面可可靠辨識時才以區間呈現；否則必須標示圖面估計或資料不足，不以虛構的精確價位補齊通知。

## 持久化與通知邊界

- `anchor_context` 只存在 schema v5／market structure state v3。
- prepare 階段可以把既有 v2 狀態在記憶體升級為空白 v3 anchor context，但不得提前寫回。
- 只有分析通過 contract、狀態轉移與交易憲法驗證後，finalize 才能原子保存 v3。
- 新候選、確認／失效、控制權改變與象限改變可強制通知；單純延伸既有錨的極值不會每分鐘洗版。
- 使用者可見輸出仍固定九欄；`anchor_context` 不形成第十欄。

## 部署門檻

RC 完成靜態與單元測試後，仍須以歷史順序回放及不發送 Telegram 的 shadow 觀察，驗證 `n=2／n=3` 等定錨尺度敏感度、訊號延遲及象限頻繁切換情形。正式切換只能在使用者另行同意後進行，且需保持同一 Automation ID、保留 RRULE／目標 task／通知設定，並完成實際 prompt 與 schema 雜湊反向驗證。
