# 台指期 1 分 K 趨勢與交易機會監控｜啟蒙交易＋道氏三兄弟正式分析規則

- 分析規則版本：`enlightenment-integrated-v1.7-anchor-analysis`
- 基礎分析規則：`enlightenment-integrated-v1.1`
- 整合來源：啟蒙交易班、四象限戰法強化、道氏三兄弟（道氏／樞紐點／左右戰法）與交易憲法
- 部位範圍：一口單監控
- 使用方式：由本機 `trade_monitor.local_scheduler` 以固定 SHA-256 驗證後載入；Automation 執行與 relay 由對應版本管理。樞紐、防線、定錨與情境狀態使用 v5 schema／state v3 原子持久化。本正式版將定錨與動態象限嵌入原有單一流程，不增加第五種型態、第十個通知欄位、多口加碼或另一份平行答案。

## 0. 核心原則

本監控只有一套判斷，不把四象限、號盤、箱型品質、樞紐、道氏或左右戰法做成與原規則平行的第二套分析。

固定順序為：

**最新已收盤 1 分 K → 更新樞紐候選／確認／失效 → 1 分 K 同級道氏結構 → 較大級數與 5／15 分脈絡 → 同時更新大小級多／空道氏防線 → 更新初始錨、反向錨與目前控制級數 → 延續、Type 1／2／3 或級數升級 → 大趨勢／當前趨勢 → 由錨後波段的趨勢性與波動變化更新號盤及動態象限 → 波段階段、所在位置、兩條情境路徑與級數一致性 → 從原有四種型態選一種並標示左左／左右／右左／右右成熟度與準備／觸發階段 → 失效與交易憲法 → 結構停損、R與最近障礙 → 一口單管理 → 通知。**

各課程概念在現行規則中的用途：

- **號盤**：限制方向；不單獨觸發進場。
- **四象限**：決定原有四種型態是否適用；不增加第五種型態。
- **S／S／T／V**：決定開盤區間或壓縮箱型是否合格；不獨立發訊號。
- **交易憲法**：決定即使型態完成，是否仍禁止新交易。
- **樞紐點**：客觀化現有的高低點推進與拉回極值；不新增第五種型態。
- **道氏防線與三種反轉**：改寫現有的方向失效、有效翻轉與持倉退出；不另做第二套趨勢答案。
- **左左／左右／右左／右右**：只表示反轉訊號成熟度與可否執行，不代表四份部位；本版始終只管理一口。
- **定錨／反向定錨**：提供號盤、象限與大小級情境的共同起點；不單獨觸發進場，也不覆蓋既有四型態的停損與確認條件。

不得為了每分鐘提供方向而硬湊交易。正確等待也是有效監控結果。

本文件所有方向規則都必須採**多空完全鏡像**。以反彈做空說明的條文，必須同時套用為拉回做多的鏡像；以支撐守住說明的條文，也必須同時套用為壓力受阻的鏡像。不得因範例只寫單一方向，就停止辨識另一方向的樞紐、防線、型態或通知。

## 2. 資料紀律與時間錨定

1. 每次先辨識最新已收盤 1 分 K。當前未收盤即時 K 只能描述正在測試的支撐、壓力、拉升或回落，不能完成型態、確認進場、確認停損或建立模擬持倉。
2. 執行途中跨入下一分鐘時，不追逐新 K；下一輪再處理。
3. 可由連續 1 分 K 合成 5 分與 15 分脈絡。1 分 K 是觸發級數、5 分 K 是結構與持倉保護級數、15 分 K 是較大方向脈絡；不得只因單根 1 分 K 改寫大方向。
4. 可見歷史不足時明寫「可見資料不足」，不得杜撰。
5. OHLC、均價 21、均價 105、ATR、支撐與壓力一律標示「圖面估計」並使用區間。圖上直接標記的單點也只作估計參考，不可冒充實際成交價。
6. 每輪先識別時段：
   - 08:45 日盤開盤／日盤時段。
   - 15:00 夜盤開盤。
   - 夜盤下午／美股開盤前。
   - 美股開盤後；依當日夏令 21:30、冬令 22:30 台灣時間處理。
7. 日盤與夜盤是不同交易時段，各自重設號盤。美股開盤區間是夜盤內的重要新區間，但不重設夜盤號數。
8. 若距上次處理新增超過一根已收盤 K，只用缺口內 K 棒重建現在的結構、號盤、象限、候選及持倉風險，不回補歷史成交。
9. 若訊號可能在時間缺口內完成，但目前已離觸發區過遠，寫「訊號曾完成，但現在不宜追價」，只列下一個仍可執行的回踩、再突破或失效條件。

## 3. 大趨勢與當前趨勢

### 3.1 大趨勢

使用最近約 45～90 分鐘，綜合：

- 價格相對均價 105 的位置。
- 均價 105 斜率。
- 合成 5 分 K 的高低點推進。
- 從 1 分 K 一級樞紐升級而來的二級樞紐方向，以及大級數道氏防線是否仍有效。
- 對應時段的開盤價、開盤區間與本時段高低點是否被突破並守住。

分類仍固定為：

- 強勢偏多
- 偏多但回檔
- 盤整
- 偏空但反彈
- 強勢偏空
- 資料不足

### 3.2 當前趨勢

使用最近約 5～20 分鐘，綜合：

- 價格相對均價 21 的位置。
- 均價 21 斜率。
- 最近 K 棒高低點推進。
- 已配對確認的一級樞紐排列、當前一級道氏防線與其是否被收盤突破。
- 突破、回踩或反彈是否延續。

分類固定為：

- 偏多
- 偏空
- 盤整
- 轉換中

### 3.3 趨勢使用原則

- KD 與 MACD 只作動能輔助，不能單獨觸發。
- 大趨勢偏多、當前偏空時，先視為回檔，等待重新轉多；大趨勢偏空、當前偏多時，先視為反彈，等待重新轉空。
- 逆大趨勢訊號只能是觀察，除非後述「有效方向翻轉」已成立並使號盤增加。
- 大趨勢使用最大日內級數，當前趨勢使用下一至兩個次級架構；不可只更換觀看級數來替虧損方向辯護。
- 一級與二級樞紐同向時，直接反映為大趨勢與當前趨勢同向；兩者不同向時，依防線是否被破分類為回檔／反彈或轉換中，不另輸出「共振監控」。
- 若樞紐、防線、均線與合成 5／15 分結構互相矛盾，採較保守分類並明寫「結構不一致」；不得挑選最有利於既有方向的證據。
- 目前固定資料源沒有可靠日線樞紐、期貨換月與夜盤歸日狀態，因此不自行套用課程的日線單向濾網；只使用畫面可驗證的 1／5／15 分與最近 45～90 分鐘脈絡。

## 3A. 樞紐、道氏防線、反轉型態與左右成熟度

本節不是新增一層平行監控，而是把現行規則中的「高低點推進、最後防守波段、有效方向翻轉、拉回與再突破」改成可重複的結構定義。

### 3A.1 一級樞紐：固定參數與即時狀態

1. 本正式分析規則固定使用 `n=2` 作為一級樞紐參數；不得盤中因結果不好而改成 1、3 或 4。`n=2` 與 `n=3` 的因果回放比較保存在版本庫驗證報告；該比較只驗證結構密度、延遲與重畫代理，不構成獲利能力證明。
2. 某根 K 收盤後，若其左側兩根已收盤 K 的高點都嚴格低於它，可先標成「潛在高點候選」；候選 K 本身不得算入左側兩根。
3. 高點候選後續依序滿足以下條件才算局部成立：
   - 右側完整兩根已收盤 K 的高點都嚴格低於候選 K 高點；候選 K 本身不得算入右側兩根。
   - 候選 K 的低點已被候選之後的已收盤 K **收盤跌破**。
4. 低點樞紐完全鏡像：左側兩根低點都較高時先成潛在候選；右側完整兩根低點也都較高，且候選 K 高點被後續已收盤 K **收盤突破**後，才算局部成立。
5. 相等高點／低點的平臺不硬選其中一根為唯一樞紐；先視為同一極值區。直到可辨識的唯一極值與左右兩根條件成立，否則標示「樞紐未定」。
6. 每個點依序標示：`候選 → 局部成立 → 配對確認`，或在配對前成為 `失效／被更極端點取代`。最新同向點在相反樞紐形成前仍可重畫，不能冒充事前已知的完成點。
7. 高、低樞紐必須交替配對。同方向出現更極端候選時，只保留較極端者作最新候選，並保留原判斷發生時間；不得事後改寫成當時已經知道新點。
8. 純截圖無法可靠確認精確 OHLC、左右根數或候選 K 高低被收盤突破時，標示「圖面估計／樞紐未定」，不得強行建立防線或翻向。
9. `context.expected_latest_closed_k_iso` 是最右側最新已收盤 K 的時間錨。只有畫面可清楚分辨連續一分鐘 K 棒邊界、最新已收盤 K 位置及中間沒有可見缺口時，才可由最右側向左逐根計數，將某根 K 的時間推回相同分鐘數；這只是結構時間定位，不代表知道精確 OHLC。K 棒邊界、最右端位置或連續性任一不清楚時，不得用目測距離猜時間。
10. 價軸不足時，樞紐的 `price_estimate` 使用 `null`，並在 notes 標記「圖面估計／價格未定」；不得只因價格不能可靠估算，就捨棄一個已能由清楚相對高低、左右根數與收盤實體位置確認的候選或局部成立樞紐。
11. 前次快照沒有、這一輪才首次辨識的舊 K 樞紐，其 `bar_time` 保留實際推回的 K 棒時間，但 `first_seen_at` 必須使用本輪 `context.expected_latest_closed_k_iso`；不得把首次看見時間回填成樞紐 K 時間。之後局部成立或配對確認時，也只在狀態第一次真正成立的本輪寫入對應首次確認時間。

### 3A.2 比例疑慮與二級樞紐

1. 課程未提供比例原則的量化公式。本正式分析規則不擅自刪除形式成立的樞紐；只要轉折明顯侷限於箱體中央、遠小於相鄰主要波段，或造成密集來回，就標記「微型樞紐／比例疑慮」。
2. 有比例疑慮的一級樞紐可描述短線震盪，但不得單獨更新道氏防線、增加號盤或完成逆大趨勢進場；仍須同時通過防線、象限及 S／S／T／V 條件。
3. 二級樞紐只從**已配對確認的一級樞紐序列**再篩選，固定使用 `n=1`：二級高點左右各一個較低的一級高點；二級低點左右各一個較高的一級低點。高點只和高點比較，低點只和低點比較。
4. 一級樞紐負責 1 分 K 觸發與當前趨勢；二級樞紐加上合成 5／15 分結構負責大趨勢與較大道氏防線。兩者同向是方向一致，不同向則先視為修正或轉換。
5. 二級樞紐也有候選、確認與失效延遲。不得使用事後完整線段回填當時訊號。

### 3A.3 道氏狀態與防線

同一級數只使用已知樞紐序列判斷：

- `BULL`：高過高，且低不破低。
- `BEAR`：低破低，且高不過高。
- `TRANSITION`：只完成一半慣性改變，或防線剛破但反向序列尚未完成。
- `UNDEFINED`：樞紐不足、比例疑慮嚴重、平臺極值未定或箱內雜訊。

道氏防線必須符合因果順序：

- **多頭防線**：最近一個已配對確認的同級樞紐低點，且從該低點發動的上漲已造成同級前高被突破／形成新高。只有創高完成後，該低點才取得防線資格。
- **空頭防線**：最近一個已配對確認的同級樞紐高點，且從該高點發動的下跌已造成同級前低被跌破／形成新低。只有創低完成後，該高點才取得防線資格。
- 每輪必須同時辨識並保存「小級多頭、小級空頭、大級多頭、大級空頭」四個防線槽位；沒有合格防線時使用 null，但不得只更新目前想交易的方向。
- 只出現較高低點或較低高點，但尚未造成同級創高／創低時，不得提前移動防線。
- OR、箱頂／箱底、時段高低與均價仍是型態邊界或輔助結構；除非它同時符合上述因果關係，否則不得直接稱為道氏防線。
- 時段初期樞紐不足時，可把已確認的 OR 對側或第一個重要結構邊界標成「暫代失效邊界」，但必須和正式道氏防線分開命名；正式防線形成後即取代暫代邊界。
- 防線每次建立、上移、下移、被破或被後續級數升級取代，都以當時已收盤 K 為時間版本；不可事後覆寫歷史判斷。
- 同一時段內，仍為 ACTIVE 的防線不得無事件消失成 null；已配對確認的樞紐不得因下一輪裁切或模型遺漏而消失。舊防線須先標記 BROKEN／REPLACED，之後才可由新防線取代。

### 3A.4 三種反轉與級數升級

以下多轉空與空轉多完全鏡像：

1. **Type 1 警告**：小級數已形成反向道氏慣性，但較大級數原方向防線未破。現有原方向持倉可提高警戒、依原停損或保護規則退出；新反向交易最多列「條件式」，不得列「可評估進場」，號盤不增加。
2. **Type 2 確認**：原方向的有效道氏防線先被已收盤 K 突破，之後完成反向的「拉回不再恢復原高／低＋再向新方向破位」序列。這才是一般有效方向翻轉與號盤增加的主要定義；偏好等待防線突破後第一次拉回，也就是右左。
3. **Type 3 特殊 V 轉**：同一段連續推進以收盤依序穿越至少一條小級與一條大級有效防線。立即通知原方向風險，原持倉依變盤規則處理；新方向不得追第一段，必須等待第一個可辨識右左拉回，若沒有合理停損與空間就放棄。
4. **級數升級／重分類**：某級防線被破後，行情又沿原方向創出同級或更大級新高／新低。從該根已收盤 K 起重新分類為較大級數，不回頭宣稱前次防線沒有被破；原候選、號盤與持倉事件保留歷史版本。

### 3A.5 左左、左右、右左、右右在一口單規則中的用途

四個名稱只標示**反轉候選的成熟度**，不是四份部位，也不增加新型態：

| 階段 | 結構定義 | 本監控允許動作 |
|---|---|---|
| 左左 | 原方向大防線未破，只見末段加速、次高／次低或背離等衰竭線索 | 只觀察；技術背離不能單獨觸發，不建立模擬倉 |
| 左右 | 原方向大防線未破，但小級樞紐已形成反向慣性 | 最多條件式；視為 Type 1 警告，不建立逆向模擬倉 |
| 右左 | 原方向防線已破，等待第一次反向趨勢的有效拉回／反彈守住 | 本一口單系統的優先可執行階段；仍須通過號盤、象限、四種型態、憲法、停損與空間 |
| 右右 | 右左完成後再突破／跌破延續樞紐 | 可評估但不得遠端追價；停損以右左整段極值為主，太遠就等待下一次右左 |

- 左＝防線尚未被突破的猜測區，右＝防線被有效突破後的確認區；不是圖面幾何左右，也不能事後用全日最高／最低點切割。
- 普通順勢行情的「趨勢拉回延續」可直接視為同方向的右左／右右成熟度，不必硬從左左重新開始。
- 左側位置可能較好但確認較少；右側確認較多但追價與停損距離可能變差。此取捨只用來說明品質，不使用課堂口述勝率當成系統參數。
- 第三次攻擊、第五波、背離與持倉者心理只能補充「可能處於趨勢後段」的背景，不能單獨改變趨勢、號盤、Type 或候選狀態。
- 課程的四份等分、直接進入右側時補足兩份及順勢加碼全部不納入本一口單版。
- 左右戰法必須加入通知情境，且多空鏡像：左左進入左右、防線突破由左進右、進入右左觀察區、右左完成積極／保守確認、右右延續觸發、候選失效與級數升級都屬重大事件。普通微型樞紐或成熟度未變不需重複通知。

## 3B. 定錨、反向定錨與動態象限

定錨不是新增策略，而是把「從哪一段開始比較趨勢性與波動率」固定下來。日盤與夜盤各自重設 session 結構；同一時段最多只保留一個作用中大級錨與一個作用中小級錨，終止的錨保留歷史但不再控制判斷。

### 3B.1 錨的起點、品質與生命週期

1. 日盤從 08:45、夜盤從 15:00 各自尋找第一個有效方向。日盤優先觀察現貨開盤後第一個有效段，但不得把第一根 K 的顏色機械當成錨；夜盤沒有現貨開盤條件，改用夜盤 OR、時段極值、結構或防線破壞。
2. 初始錨起點使用方向段發動前最後一個已知、同級且合格的反向樞紐；時段初期樞紐不足時才使用時段開盤或 OR 邊界，並明寫依據。
3. 錨候選至少要有清楚方向位移，且品質不得為不合格。品質只用：
   - `CLEAN`：影線與重疊少、轉折少、方向位移清楚且仍有可用空間。
   - `CAUTION`：方向存在，但影線、重疊、幅度或可見資料有一項疑慮。
   - `UNQUALIFIED`：位移侷限於雜訊、轉折密集、幅度不足或已耗盡可用空間；不得確認成有效錨。
   - `UNKNOWN`：圖面不足。
4. 課程的 `20 日 ATR × 1/4 或 1/5` 只作有完整日資料時的研究參考。純一分 K 截圖沒有可靠 20 日 ATR 時，改用可見 20～30 分鐘波段、OR 尺寸、圖上可辨識 ATR 與最近主要推進作相對比較，不得杜撰日線 ATR。
5. 有效錨必須有至少一項可驗證的破壞／守住證據：OR 突破守住、時段高低突破、重要結構突破、同級防線突破、現貨開盤第一方向守住、穿頭破底／破底穿頭，或 Type 3 同段穿越大小防線。
6. 狀態固定為：`FORMING → CONFIRMED → INVALIDATED／REPLACED`。候選尚未確認時 `confirmed_at=null`；確認與終止時間只能在當輪首次成立時寫入，不能回填。
7. `anchor_id`、級數、方向、來源、起點 K 與 `first_seen_at` 一經保存不得改寫。形成中或已確認的錨可隨新收盤 K 延伸極值，但極值時間不得倒退，多方極值不得向下改、空方極值不得向上改。
8. 純截圖可看清相對結構但無法可靠估價時，保留錨及時間，價格使用 null、失效區標 UNAVAILABLE；不得捏造點位，也不得只因點位未知而刪掉可驗證的錨。
9. 錨確認以前原則上不建立一般趨勢模擬倉；但 OR 回踩或既有四型態若其確認事件本身同時完成初始錨確認，可在同一根已收盤 K 後依原型態評估，不必再額外等待一輪。

### 3B.2 反向定錨與既有 Type／號盤的對應

1. 只破小級防線並形成反向小級慣性：建立小級反向錨候選／確認，大級原錨仍有效；對應 Type 1／左右，號盤不增加。
2. 原方向大級有效防線被破，之後完成反向拉回不恢復原方向並再破位：舊工作錨終止，新方向錨確認；對應 Type 2／右左，號盤增加。
3. 同一段連續穿越大小兩級有效防線：可確認 Type 3 急速反向錨並終止受影響的原錨，但新方向仍等待第一個右左拉回，不追第一段。
4. 小級反向錨不得清除仍有效的大級錨；只有大級防線、Day High／Day Low、同級重要結構或 Type 3 大小防線同破，才可重置大級錨。
5. 作用中錨切換前，舊錨必須先標 `INVALIDATED` 或 `REPLACED` 並記錄終止時間；不得讓 ACTIVE 錨無事件消失。
6. 0 號盤方向直接取本時段第一個已確認的 session 工作錨方向。1 號及其後號數仍只在 Type 2／3 的有效反向錨確認後增加，不另保留第二套第一方向規則。

### 3B.3 大小級控制權與單一工作答案

1. 大級錨提供大趨勢、潛在空間與主要失效背景；小級錨提供當前趨勢、目前發球權與進場時機。
2. 大小錨同向時標 `ALIGNED`；方向衝突標 `CONFLICT`；只有一層可用時標 `ONLY_LARGE／ONLY_SMALL`。這些直接映射既有 `grade_alignment`，不另生成「共振策略」。
3. 大小衝突時，小級錨未失效前可暫時掌握 `controlling_grade=SMALL`，但逆大級方向只能條件式、降低品質與目標；小級失效後控制權立即回到大級錨。
4. 使用者可見通知始終只有一個工作象限與一套操作情境。大級錨寫在大趨勢作背景，小級錨寫在當前趨勢作時機；不得輸出兩份互相競爭的多空建議。

### 3B.4 從錨後波段動態更新象限

錨剛形成、只有第一段時，象限標「轉換中」，最多排列主要／次要候選。從第二、第三段開始，以刪除法質性排序，不輸出虛假的百分比：

| 錨後結構 | 動態象限結論 |
|---|---|
| 同向持續創新極值，推進段與 K 棒振幅擴張 | Q1 上升；確認後使用動能型管理 |
| 原方向與防線未破，同向推進仍延續但幅度／振幅收縮 | Q4 上升；等待區域型拉回 |
| 多空交替破位、兩側振幅擴張、方向無法守住 | Q2 上升；只用外圍擴張失敗反轉 |
| 無法延續創高／創低，重疊增加且波段／振幅收縮 | Q3 上升；原則觀望 |
| 作用中錨的同級防線被破 | 原象限立即改為 TRANSITION；等待原錨恢復或反向錨確認 |

每輪 `anchor_context` 必須保存：所有錨及其因果時間、作用中大小錨、目前控制級數、大小關係、趨勢性增／減／不明、波動擴張／收縮／不穩、工作象限、主要／次要候選、已排除象限、理由及首次變更時間。普通錨極值延伸不單獨強制通知；錨候選建立、確認／失效、作用中錨或控制級數切換、主要象限候選／工作象限改變才屬重大事件。

**尚無任何因果錨時，`working_quadrant` 與主要候選都必須是 `UNDEFINED`，次要候選為 `null`，已排除象限為空；不得只憑均線或單張快照先填 Q1～Q4 候選。** 至少建立一個當輪可見且不回填的 `FORMING` 錨後，才可進入 `TRANSITION` 並排序象限候選。

不得研究或硬編碼「某象限下一步固定轉去哪一象限」。象限看法只因最新已收盤 K 造成上述結構改變而更新；變盤代表原理由失效，不等於立即反手。

### 3C. 波段階段、位置、兩條路徑與級數一致性

每輪都要在同一份市場狀態中更新以下四項，不另產生平行策略：

1. **波段階段**：推進初段、中段、末段、拉回、反彈、轉換、盤整或資料不足。不得只因第三次攻擊、第五波或背離就宣稱末段，必須同時參考推進距離、防線與 5／15 分結構。
2. **所在位置**：支撐、壓力、前高、前低、道氏防線回測、原突破區、箱型邊界或箱型中央。位置不清楚時明寫資料不足。
3. **兩條情境路徑**：固定同時說明「關鍵位置守住／受阻」與「關鍵位置被有效突破／跌破」後各需什麼收盤確認及下一個可觀察區；這是條件推演，不得宣稱預知一定走哪條路。
4. **級數一致性**：大方向、目前型態、觸發級數與停損結構分類為一致、部分一致、不一致或資料不足。小級型態若需要大級停損，必須降級品質或等待較淺的同級拉回，不得用方向正確掩蓋級數錯配。

圖面可可靠辨識時，情境必須給觀察區、觸發區、失效／停損區及最近障礙區的圖面估計範圍；無法可靠估計時，逐項明寫「圖面不足，暫不提供可靠區間」及原因，不得默默省略。

## 4. 號盤：嵌入既有方向判斷

### 4.1 狀態

每個日盤或夜盤時段只使用：

- 號盤未定
- 0 號盤向上／0 號盤向下
- 1 號盤向上／1 號盤向下
- 2 號盤以上

### 4.2 第一個方向

時段開始時先標示「號盤未定」。只有本時段第一個 session 工作錨由已收盤 K 確認後，才以該錨方向建立 0 號盤。下列來源是初始錨的確認證據，不再獨立產生另一個方向：

- OR5 或 OR15 有效突破並守住。
- 明確時段高低點或重要結構被突破並守住。
- 日盤開盤已明確改變夜盤結構，且 5 分 K 高低點推進與當前趨勢同向。

不能只因第一根 K 棒顏色或均價 21 短暫斜率決定 0 號方向。

### 4.3 有效方向翻轉

號數只在「主要方向真正失效並形成新方向」時增加。正式判斷順序如下：

1. 已收盤 1 分 K 突破目前方向的**有效同級道氏防線**。時段初期尚無正式防線時，才使用已標明的 OR 對側或第一個重要結構作「暫代失效邊界」；均價 21、任意支撐壓力或未取得資格的高低點不能取代防線。
2. 防線突破本身先把當前趨勢標為「轉換中」，不立刻增加號數；突破不能只是影線，且至少符合以下一項：
   - 下一根已收盤 K 仍守在新方向一側。
   - 合成 5 分 K 已完成原方向結構破壞。
   - 均價 21 已轉向，回測原防線／暫代邊界失敗後再向新方向發動。
3. 一般情況必須完成 Type 2 的反向樞紐慣性，且當前趨勢已轉成新方向，才把號數加一。只有同一段推進已構成 Type 3、同時收盤穿越小與大防線，才可在當前趨勢確認翻向時先增加號數，但新倉仍須等待右左拉回。
4. Type 1 只有小級慣性改變而大防線未破，號數不增加；若仍是「轉換中」，也暫不增加。
5. 防線被破後原方向又創新極值時，記為級數升級／重分類。若翻向尚未確認，不增加號數；若翻向已確認，號數作為已發生的方向轉換歷史不得倒扣，後續再依新結構判斷下一次翻向。

單根影線、短暫穿越均價、兩根內收回的假突破、微型／比例疑慮樞紐，以及箱內中央來回都不計號數。

### 4.4 號盤對既有型態的約束

- **0 號盤**：順第一方向的開盤突破回踩、趨勢拉回與壓縮突破優先。
- **1 號盤**：只有 Type 2／Type 3 的有效翻轉完成後，新方向才能使用順勢型態；原方向候選全部失效，不能同時保留多空兩套進場理由。Type 3 不追第一段，仍等待右左。
- **2 號盤以上**：視為方向反覆、趨勢優勢明顯下降。禁止一般趨勢追價與普通壓縮突破；只允許明確外圍邊界的假突破／假跌破反轉，否則觀望。
- 本監控預設採課程中的 **0 號導向**：先跟隨第一個有效方向。1 號翻向是條件式例外，不是預先同時尋找雙向交易。

## 5. 四象限：改寫既有市場狀態與型態准入

四象限只描述趨勢性與波動率，不代表多空方向。

四象限必須從作用中錨之後的已知波段動態比較；均線、5 分 K、OR 與 ATR 只作交叉驗證。尚無合格錨、只有第一段、作用中錨防線剛被破或大小錨嚴重衝突時，標示「象限轉換中」，不得用單張快照硬貼 Q1～Q4。

每輪必須同時更新 `trend_dynamics` 與 `volatility_dynamics`，再以主要候選、次要候選與刪除理由形成唯一工作象限。不得以固定數值機率宣稱下一象限。

### 5.1 趨勢性

趨勢性高：大趨勢不是「盤整／資料不足」，且以下至少兩項清楚成立：

- 價格大多位於均價 105 同一側，均價 105 具有同向斜率。
- 合成 5 分 K 至少兩段呈同向高低點推進。
- 開盤區間、本時段高低點或重要結構已被突破並守住。

趨勢性低：大趨勢為盤整，或上述條件最多只成立一項。介於兩者或剛被破壞時標示「象限轉換中」，不得硬判。

### 5.2 波動率

波動率高：以下至少兩項成立：

- 最近約 5～10 根 K 的典型振幅相對前 15～20 根明顯擴張。
- 實體與波段推進距離擴大，出現連續大實體或快速拉回。
- 圖面可辨識的 ATR14 正在上升。

波動率低：K 棒振幅收斂或保持穩定、重疊增加，且沒有孤立大 K 破壞結構。若大小 K 棒交錯、影線失控或無法判斷，標示波動不穩定，不得當成低波動箱型。

### 5.3 象限

| 象限 | 狀態 | 原有型態的使用方式 |
|---|---|---|
| 第一象限 | 趨勢高、波動高 | 優先順向開盤突破回踩、同向壓縮突破、趨勢拉回；偏動能管理 |
| 第二象限 | 趨勢低、波動高 | 只保留明確外圍邊界的假突破／假跌破；等待方向重新成立 |
| 第三象限 | 趨勢低、波動低 | 只評估合格箱型壓縮突破或外圍假突破；中央禁止 |
| 第四象限 | 趨勢高、波動低 | 優先趨勢拉回、順勢低接／反彈及收斂後再發動；禁止遠端追價 |

四個象限都必須監控並通知各自允許的型態，不是只有第四象限：第一象限通知順向動能、突破回踩與趨勢拉回並提醒追價風險；第二象限通知外圍假突破／假跌破而禁止普通壓縮；第三象限通知合格箱型壓縮或外圍假突破而禁止中央；第四象限以趨勢拉回的準備與重新發動為優先。

### 5.4 與原本盤整規則的關係

原本盤整判斷繼續使用：

- 均價 105 近乎走平。
- 最近 10 根至少三次穿越均價 21。
- 最近 20～30 分鐘高低範圍明顯重疊。

三項符合兩項即判為低趨勢性；再依波動判成第二或第三象限。不能把所有盤整都當成可做壓縮突破的第三象限。

## 6. 箱型 S／S／T／V：嵌入 OR 與壓縮型態

只要候選涉及 OR5、OR15、盤中壓縮或盤整箱體，就在原「觀察型態與狀態」內完成四面向檢查：

1. **S－尺寸／級數**：區間寬度是否符合目前 1／5 分架構；結構停損是否合理；最近障礙是否留下可用空間。
2. **S－穩定度**：多數收盤是否留在清楚邊界內；影線是否反覆刺穿；K 棒是否乾淨而非雜亂掃動。
3. **T－趨勢性**：箱前方向、號盤與象限是否支持預定突破方向。
4. **V－波動品質**：波動是否收斂或穩定；不得大小 K 棒交錯、突然擴張又立刻收回。

純截圖無法可靠產生精確 1～5 分，因此只用：

- **合格**：四項皆可辨識且至少三項明確支持，沒有硬性否決。
- **警戒**：只有三項可辨識或其中一項偏弱；只能列條件式候選，不能直接列可評估進場。
- **不合格**：兩項以下支持，或出現任一硬性否決。

硬性否決包括：

- 位於箱體中央 50%。
- 邊界被反覆收盤穿越，沒有穩定箱頂／箱底。
- 長影線密集或大小 K 棒失控。
- 箱體太寬，使結構停損相對最近障礙明顯不合理。
- 2 號盤以上卻試圖在箱體中央做普通突破。
- 可見資料不足，無法辨認至少三個面向。

S／S／T／V 只決定既有型態是否合格，不新增通知欄位或獨立訊號。

## 7. 四種既有型態：整合後的完整規則

方向均可對稱，但必須先通過號盤、象限與交易憲法。

### 7.1 開盤區間突破回踩

#### 日盤 OR15

- 使用 08:45～08:59 共 15 根已收盤 1 分 K 建立區間。
- 09:00 起適用，最高點為箱頂、最低點為箱底。

#### 日盤 OR5

- 使用 08:45～08:49 前 5 根已收盤 1 分 K。
- 僅於 08:50～08:59 提供較早候選。
- 必須全部成立：
  - 突破方向與夜盤最近 45～90 分鐘趨勢一致，或日盤開盤已明確改變夜盤結構。
  - 突破 K 實體明顯，不能主要由長影線構成。
  - 第一次回踩未收進 OR5 中央 50%。
  - 其後已收盤 K 再次向突破方向突破回踩小區間。
  - S／S／T／V 至少為「警戒」，且沒有硬性否決。
- 條件不足就等待 OR15，不得降低標準。
- 09:00 後 OR5 不再產生新訊號；已存在候選或模擬持倉仍依原失效與管理規則追蹤。

#### 夜盤與美股開盤

- 15:00～15:14 的 15 根已收盤 1 分 K 建立夜盤開盤區間，15:15 起適用。
- 美股現貨開盤後前 15 分鐘另建新區間，但不重設夜盤號盤。

#### 共同觸發

- 已收盤 K 突破區間，沒有立即收回。
- 等待第一次回踩突破位置。
- 回踩守住後，由已收盤 1 分 K 向突破方向重新發動。
- OR 突破本身只完成方向事件；第一次回踩守住屬右左，再發動屬右右。沒有回踩就急拉者不得因右右確認度較高而追價。
- 第一象限、0／已確認 1 號盤順向訊號可以列「可評估進場」。
- 第四象限需等待回踩更靠近結構，不可把遠離區間的突破當成低接。
- 第二象限不得使用一般 OR 突破；只能等待其演變成假突破反轉。
- 第三象限需 S／S／T／V 合格，且突破後最好有回踩確認。
- 進場只寫「確認後下一根第一個可成交價格可評估」。已遠離觸發區則不追價，等待第二次回踩。
- 開盤區間中央 50% 禁止交易；上下邊界反覆突破又收回視為開盤震盪。

#### 失效與停損

- 候選在突破後立即收回區間，或回踩收破突破邊界，失效。
- 結構停損位於整段回踩區間極值外，加上後述緩衝。

### 7.2 趨勢拉回延續

- 只在第一或第四象限、0 號盤或已確認的 1 號新方向使用。
- 大趨勢明確，當前趨勢逆向拉回至均價 21、原突破位置或重要支撐／壓力。
- 本型態多空完全鏡像：多方等待拉回止跌後重新轉強；空方等待反彈受阻後重新轉弱。
- 採兩階段通知。第一階段是 `FORMING／ARMED`：價格進入均價 21、原突破／跌破區、同方向道氏防線或重要支撐／壓力附近，且逆向推進開始停止；此時只列條件式，不建立模擬倉。
- 第二階段分兩種完成度，但仍是同一個「趨勢拉回延續」型態：
  - **積極確認**：已收盤 1 分 K 在觀察區完成多方止跌重新轉強，或空方反彈受阻重新轉弱；必須能指出觸發行為及完整拉回／反彈極值。可列可評估進場，但訊號品質低於保守確認。
  - **保守確認**：已收盤 1 分 K 再突破／跌破最近約 3～8 根拉回／反彈 K 形成的小區間；訊號確認較高，但仍須檢查是否離結構過遠。
- 拉回極值應優先由已局部成立或配對確認的一級樞紐辨識；截圖不足以完成樞紐時，才保守使用完整 3～8 根拉回區間，並註明「樞紐未定」。
- 第一象限屬動能後拉回，同樣使用準備／觸發通知，容許較快確認但不得追大實體 K；第四象限是此型態的優先環境，應更早通知進入觀察區並重視結構完整、風險較小及趨勢仍未失效。
- 第二、第三象限不使用一般趨勢拉回。
- 此型態在已建立的同方向趨勢中直接視為右左；突破拉回小區間則是右右確認，不必硬找同一畫面內的左左／左右。
- 必須能指出整段拉回極值、同級道氏防線與大趨勢失效點。拉回未造成原方向創新極值前，不得只因出現一個新樞紐就提前移動防線。
- 停損在整段約 3～8 根拉回區間極值外，加上緩衝。

### 7.3 盤中壓縮突破

- 最近約 10～20 根振幅與推進縮小，均價 21 走平後重新轉向。
- S／S／T／V 必須「合格」才可列可評估進場；「警戒」只能列條件式候選。
- 第三象限是標準環境；等待已收盤 K 突破壓縮邊界，最好再有回踩或下一根守住。
- 第一或第四象限可做同向再壓縮突破，但方向必須與號盤及大趨勢一致。
- 若壓縮突破試圖逆轉原趨勢，但原道氏防線未破，它最多是左右／Type 1 條件式警告；不得因小箱突破直接反手。
- 若壓縮發生於已確認新方向，第一次突破後回踩守住可視為右左，再突破為右右；仍維持本型態名稱，不另增加「左右戰法型態」。
- 第二象限禁止普通壓縮突破，因為高波動雜訊不等於低波動壓縮。
- 2 號盤以上禁止箱內普通突破。
- 下一根立即收回壓縮區，候選失效。
- 停損位於壓縮區另一側或最近明確失效位置外，加上緩衝。

### 7.4 假突破／假跌破反轉

- 僅限明確箱頂、箱底、日盤／夜盤／美股開盤區間邊界或重要時段高低點。
- 快速假突破路徑：突破邊界後最多兩根已收盤 1 分 K 內收回，且無法重新站回突破方向；再由已收盤 K 向箱內方向突破「收回確認 K」的高／低點，才完成觸發。
- 第二象限的較慢外圍擴張失敗仍歸本型態，不增加第五種型態：必須位於明確外圍邊界，先證明突破無法延續，再形成反向小級錨、完成右左拉回與再發動；箱體中央、只有單根反色 K 或沒有結構失效者不得使用。
- 假突破收回可構成左左或左右線索，但在原方向有效道氏防線未破前，逆勢方向只能觀察／條件式，不建立模擬倉。
- 箱體中央不得使用。
- 第二象限是主要適用環境，但要降低期待，目標先看最近結構；不可把每次劇烈拉回都當反轉。
- 第三象限可在合格箱型外圍使用。
- 第一／第四象限若反轉方向逆大趨勢，只列觀察；除非同時完成 Type 2／Type 3 有效方向翻轉、號盤增加且大趨勢轉換。可執行位置優先等待防線突破後右左；右右若離結構太遠則禁止追價。
- 停損位於假突破極值外，加上緩衝。

## 8. 候選狀態與准入

只使用：

- **觀望**：沒有合適型態，或資料不足。
- **條件式偏多／偏空**：方向存在，但仍缺收盤價位、回踩守住、象限確認、號盤確認或箱型品質。
- **可評估進場**：最新已收盤 K 已完成原型態觸發，且號盤、象限、S／S／T／V（如適用）與交易憲法均未否決；列出下一根評估方式。
- **不宜追價／禁止**：方向可能正確，但位置、停損、象限、號盤、箱型品質或交易憲法不合適。

所有獲准使用的型態都採相同候選生命週期，不只第四象限：

- `FORMING`：型態開始形成，對應觀望或條件式。
- `ARMED`：已進入觀察區且方向存在，只差明確收盤行為，仍是條件式。
- `AGGRESSIVE_CONFIRMED`：積極確認完成；只有原型態全部硬條件、停損與空間均合格才可列可評估進場。
- `CONSERVATIVE_CONFIRMED`：保守確認完成；仍須檢查下一根可成交位置及追價距離。
- `INVALIDATED`：候選失效。
- `NO_CHASE`：方向可能正確，但已離觸發／結構過遠。

同一 setup 的階段只能因最新已收盤 K 向前推進，不能事後倒退或改寫首次形成時間。型態進入 FORMING／ARMED 後，四組區域必須持續更新：觀察區、觸發區、失效／停損區、最近障礙區；區域改變或由可估計變成不可估計時必須通知原因。

「可評估進場」必須同時回答：

1. 是四種型態中的哪一種。
2. 目前相關樞紐與道氏防線是否確認；若是反轉候選，屬 Type 1／2／3 與左左／左右／右左／右右何階段。
3. 目前號盤與象限為何，為何允許此型態。
4. 哪一根已收盤 K 完成什麼觸發。
5. 下一根從哪種行為評估，不使用歷史觸發價假裝可成交。
6. 結構失效位置、停損區間、點數風險、1R與最近障礙。
7. 是否受到冷卻或其他禁止條件限制；模擬進場次數只作復盤統計，不構成每日准入上限。

左左與逆大趨勢的左右一律不能列「可評估進場」。右左是本一口單反轉交易的優先執行階段；右右必須另外通過不追價與風險空間檢查。

## 9. 結構停損、風險與交易憲法

### 9.1 結構停損

- 開盤突破回踩：整段回踩區間極值外。
- 趨勢拉回：整段約 3～8 根拉回區間極值外。
- 壓縮突破：壓縮區另一側或最近明確失效位置外。
- 假突破／假跌破：假突破極值外。
- 反轉右左：防線突破後第一次完整拉回／反彈的極值外。
- 反轉右右：原則上沿用右左整段極值，不得只放在突破 K 旁；若距離太遠使風險品質不合理，禁止追價並等待下一個右左結構。
- 緩衝使用 `max（2 點，0.2 × ATR14）`。ATR 無法辨識時只回報最低 2 點緩衝，並註明實際仍需依波動放大。
- 停損必須先放在策略真正失效的位置，再評估風險；不得為讓風險點數變小而塞進 1 分 K 雜訊。

### 9.2 回報風險

- 回報圖面估計進場區、結構停損區、風險點數、1R、最近障礙、可用空間與訊號品質。
- 順大趨勢的突破／延續不因「停損大於 1.2 ATR」或「第一障礙不足 1.5R」被機械否決，但必須說明風險品質；若停損明顯太遠，等待第二次較淺回踩。
- 盤整與假突破仍須有合理目標空間；箱體中央或目標不足以補償風險時禁止。
- 未知道使用者交易的是 TX、MTX 或 TMF，或未提供每筆風險預算時，只回報點數與 R，不換算口數、金額或帳戶百分比。
- 課程中的每筆 1%、每日 2.5～3% 等為示例，未經使用者確認不得套用。

### 9.3 避免過度交易

- 每個原始型態最多重新進場一次；停損後至少等待一根完整 1 分 K，不得立即反手。
- 每個期交所交易日（以前一日 15:00 夜盤起，至當日 13:45 日盤結束）持續累計所有模擬進場，供整日機會與復盤統計；模擬進場次數沒有每日硬性上限，也不得因當日已累計三次或更多而否決新的合格機會。若使用者回報真實交易，真實交易與模擬進場分開計數，不得把模擬結果冒充真實紀錄。

### 9.4 情緒／連續錯誤停手機制

- 模擬狀態連續三次停損，或使用者回報實際連續三次停損／違反交易憲法後，標示「禁止新交易」。
- 停止新進場至少 30 分鐘；監控仍繼續觀察，但不發可評估進場。
- 30 分鐘後只有重新完成大趨勢、定錨、號盤、象限與可用型態判定，且市場重新可讀，才解除；時間到本身不是返場理由。
- 實際交易狀態未由使用者回報時，不推測其連續盈虧或情緒狀態。

### 9.5 一要、一不要

- 一定要：候選觸發時同時列結構停損；若無法定義停損，不得列可評估進場。
- 絕對不要：不得在虧損的模擬或使用者回報持倉上建議加碼、攤平或放寬原停損。
- 本版是一口單模式，不啟用母單與加碼單。多口模式需另行明確授權、提供總風險與修改輸出 schema 後才能加入。
- 不採用課程的左左／左右／右左／右右各一份配置，也不採用 Type 3 直接進入右側時一次補足兩份的特例；這些只保留為成熟度標籤。

### 9.6 持久化交易憲法狀態

- 執行期狀態固定存於 `.runtime/trade_monitor/constitution_state.json`，由 adapter 原子寫入並以檔案鎖保護；提示詞不得自行直接讀寫或修補此 JSON。
- 狀態只保存期交所交易日、供復盤使用且不限制每日准入的模擬進場次數、連續模擬停損、`cooldown_until`、返場重新確認旗標、必要的模擬持倉識別、各原始 setup 使用次數及已處理事件去重資料；不得保存帳號、餘額、保證金、實際損益、Token 或 Chat ID。
- 期交所交易日以前一日 15:00 起算；13:45～14:59 禁止建立新模擬倉，15:00 第一根有效資料自動切換為下一交易日並重設每日計數。
- 成功的非停損模擬出場會把連續模擬停損歸零；取消、未成交與單純候選失效不計為進場或停損。
- 連續三次模擬停損後，30 分鐘期滿仍維持 `requalification_required`；只有重新完成大趨勢、定錨、號盤、象限與可用型態判定時，才可送出 `COOLDOWN_REQUALIFIED`，不得只因時間到自動解除。
- 每個原始 setup 的第一次進場與一次重新進場合計最多兩次。相同 K、相同 setup、相同事件重跑時，adapter 必須以持久事件去重，不可重複計數。

## 10. 一口單持倉管理

### 10.1 持倉真實性

- 使用者未回報實際成交方向、價格與停損前，只能稱「模擬持倉」。
- 若使用者回報實際持倉，後續以實際成交與初始停損計算 R。
- 不得從帳務區自行讀取持倉。

### 10.2 第一象限／動能型

- 未達 +1R 維持原結構停損，不因單根 1 分 K 正常震盪任意移動。
- 達 +1R 後等待完成的 5 分 K 有利保護位置。
- 達 +1.5R 仍無保護位置，提示停損移至成本附近。
- 後續依 5 分 K 結構移動，不固定在 +1.5R 停利。
- 若動能進場後 3～5 根已收盤 1 分 K 無有利推進，且重新收回觸發區，提示時間／行為失效可評估退出。

### 10.3 第四象限／趨勢型

- 允許較慢推進，不以單根 1 分 K 回檔過早退出。
- 未達 +1R 維持原結構停損；之後依 5 分 K 有利結構保護。
- 5 分 K 趨勢反轉、關鍵結構失守，或號盤有效翻向且象限轉為第二象限時，提示退出。

### 10.4 第二／第三象限的盤整與反轉型

- 優先看箱體中央、另一側或下一個支撐／壓力。
- 到達目標且動能停頓時提示單口退出。
- 第二象限高波動反轉的目標先看最近結構，不預設能一路走成新趨勢；若後續有效翻向成 1 號盤，再重新評估是否轉為趨勢管理。
- 第二象限反轉確認後若數根已收盤 K 仍無法離開外圍邊界、重新穿回觸發區或反向錨失效，提示時間／行為退出；課程沒有可靠固定根數，依波動與型態說明，不硬編碼講師個人點數。
- 第三象限突破若下一根立即收回，或 2～3 根內無法守在邊界外且重回中央，視為低效率失敗，不使用大停損等待回中線。

### 10.5 變盤為最後出場條件

以下同時出現時，原趨勢單不得繼續只用「長線會回來」辯護：

- 號盤已有效翻向。
- 象限由第一／第四轉為第二象限或趨勢性低。
- 5 分 K 關鍵結構已失守。

道氏反轉對既有一口持倉的處理：

- **Type 1**：只屬小級警告，不自動反手。若原型態也已失效、時間／行為失效或既有保護條件完成，可提示退出；否則維持原結構停損但不得放寬。
- **Type 2**：原方向防線與反向慣性均已確認，原方向候選立即失效；仍持有原方向單時提示退出。新方向不在確認當根追價，等待右左。
- **Type 3**：標為高風險急變，立即提示原方向風險與依原規則退出；新方向同樣等待右左，沒有可承受結構停損就放棄。
- 防線只有在新同級創高／創低完成後才更新。不得用尚未取得資格的新樞紐把保護停損過早貼近價格。

## 11. 通知決策與固定九欄

### 11.1 通知時機

- 第一次執行一定回報完整初始快照。
- 之後只在下列事件詳細通知：
  - 大趨勢或當前趨勢改變。
  - 定錨候選建立、錨確認／失效／取代、反向定錨成立、作用中大小錨或控制級數切換。
  - 動態象限主要／次要候選或工作象限改變；普通錨極值延伸不重複通知。
  - 有效道氏防線建立／移動／被收盤突破，Type 1／2／3 成立，或發生級數升級。
  - 反轉成熟度左左→左右、防線突破由左進右、進入右左觀察區、右左積極／保守確認、右右觸發、候選失效或級數升級；普通微型樞紐更新不單獨通知。
  - 號盤成立或增加。
  - 象限成立或轉換。
  - 箱型品質由警戒轉合格、轉不合格，或硬性否決出現。
  - 任一象限准入型態進入 FORMING／ARMED、積極確認、保守確認、失效或不宜追價。
  - 波段階段、所在位置或級數一致性發生足以改變交易情境的變化。
  - 已存在候選的觀察、觸發、失效或最近障礙區改變，或任一區域因圖面不足變成不可可靠估計。
  - 重要支撐壓力被收盤突破／跌破。
  - 模擬或實際持倉達 +1R／+1.5R。
  - 停損、移動停損、變盤退出或交易憲法狀態需要更新。
- 無重大變化時不要重複長文；最多每 5 分鐘一則簡短狀態。

### 11.2 固定九欄及課程資訊放置方式

保持現有 schema 與排版，不新增第十欄：

1. **時間／最新已收盤 K**：時段、新 K、資料缺口與圖面估計。
2. **大趨勢**：既有分類、45～90 分鐘／5～15 分結構、大級錨的起訖／方向／狀態／確認依據、二級樞紐及大級多／空防線脈絡。
3. **當前趨勢**：既有分類、最近 5～20 分鐘、小級錨的起訖／方向／狀態／目前控制權、一級樞紐、防線與波段階段。
4. **市場狀態**：依序寫時段、號盤、唯一工作象限、主要／次要象限候選、趨勢與波動動態、所在位置及大小級關係；總項目遵守 schema 上限。
5. **觀察型態與狀態**：四種既有型態之一，加上候選階段、S／S／T／V、Type 1／2／3（如適用）及左左／左右／右左／右右成熟度。
6. **尚缺條件／觸發**：精確列出守住／受阻與突破／跌破兩條情境、原錨延續或反向錨成立、工作象限如何維持／切換，以及型態尚缺的收盤、回踩、翻向或品質條件。
7. **進場與結構停損**：觀察區、積極／保守觸發區、下一根評估方式、失效點與停損區。
8. **1R與最近障礙**：點數風險、1R、最近障礙區、可用空間與成本／滑價提醒。
9. **單口管理／禁止原因**：模擬／實際、出場方法、交易次數、冷卻、不得攤平或其他禁止原因。

候選狀態 enum、大趨勢 enum、當前趨勢 enum 及現有 JSON 欄位名稱全部維持不變。

### 11.3 文字規範

- 使用繁體中文與 Markdown 分行條列。
- 最重要結論可適度粗體。
- 不得保證獲利。
- 每次註明：「一般技術分析，非個人化投資建議；遠端畫面可能延遲，非交易所等級即時訊號。」

### 11.4 一致雙模式

- `NOTIFY`：finalize 依 11.2 渲染完整九欄，Telegram 與 Codex 都接收同一份完整 canonical message。
- `DONT_NOTIFY`：finalize 只渲染同一則固定短版，順序為「最新已收盤 K 時間｜大趨勢｜當前趨勢｜候選狀態與型態｜notification reason」，下一行保留既有免責聲明。
- 短版只改變輸出長度，不改寫結構化分析、樞紐、防線、方向、型態、失效、停損、交易憲法或內部狀態。
- `force_notify=true` 一律升級為 `NOTIFY`，使用完整九欄並標示監控已恢復。
- event id 必須依 finalize 最後選定的完整或短版訊息計算；Telegram、outbox 與 heartbeat 不得自行換字。

## 12. 使用者實際交易回顧

當使用者回報時間、方向、成交價、停損或出場價時，切換為交易後檢討：

1. 只讀回看該時段圖表；不得因最終獲利倒推進場合理，也不得因行情事後走更遠就批評提前停利。
2. 回看進場前一根、進場當根及必要前後 K，整理當時可見的 K 棒區間、均價 21／105、大趨勢、當前趨勢、號盤、象限及 S／S／T／V；全部數字標示圖面估計。
3. 固定依序評估：
   - 當時樞紐是候選、局部成立或配對確認；是否存在未來函數或事後重畫。
   - 道氏防線是否已具備「從該點發動並創同級新高／新低」的資格，反轉屬 Type 1／2／3 或級數升級。
   - 反轉候選當時屬左左／左右／右左／右右哪個成熟度，一口單規則是否允許執行。
   - 方向是否符合當時號盤與大趨勢。
   - 象限是否允許該型態。
   - 箱型品質是否合格（如適用）。
   - 進場型態與已收盤觸發是否完成。
   - 停損是否位於整段結構真正失效處。
   - 出場是否符合事前可重複規則。
   - 是否違反交易憲法或預設 0 號交易風格。
4. 盤中突破需區分積極型盤中觸發與保守型收盤確認，但現行監控正式訊號仍以收盤確認為準。
5. 使用實際成交價計算：
   - 多單風險＝成交價－停損；獲利＝出場價－成交價。
   - 空單風險＝停損－成交價；獲利＝成交價－出場價。
   - R 倍數＝獲利÷初始風險。
   - 列出 1R 價位、實際 R、未計成本損益兩平勝率，並提醒成本與滑價會提高所需勝率。
6. 只給時間而未給成交價時，只做合理性區間分析；不得以 K 棒開收盤或觸發價冒充成交。
7. 一口單不要求事後分批；只比較固定 R 與 5 分 K 結構移動停損的可重複性。
8. 最後分列：方向、號盤／象限、進場、停損、出場、憲法／風格、最需要改善的一點，並給一致的日誌分類名稱。
9. 單次回顧不虛構長期統計。日後資料充足時，才彙總報酬率、勝率、盈虧比、獲利因子、最大回撤、交易筆數，以及不同號盤／象限／型態的績效。

## 13. Telegram 同步

以下只負責傳輸，不得改變前述分析：

1. 每輪只建立一次 `original_decision`、`latest_closed_bar_time` 與唯一決策後 canonical `message`。`NOTIFY` 使用完整九欄，`DONT_NOTIFY` 使用固定短版；不得為 Codex 與 Telegram 生成兩份不同文字。

8. Codex 顯示 finalize 原 canonical message。Telegram 接收完全相同的 message body，不接收 heartbeat、automation id、decision、event id 或 XML。
9. bridge 非 0、`ok=false`、逾時或不可解析時，在 Codex message 後另加「**TG傳送失敗：下一輪仍會繼續監控。**」；此句不回傳 Telegram。
10. `sent`、`duplicate`、`dry_run` 或 `skipped` 都不得改動 message；duplicate 不重送。

## 14. 關機／中斷恢復

1. 每輪讀圖前在工作目錄執行：
   `python -m trade_monitor.resume_guard begin --gap-seconds 180 --lease-seconds 180`
2. 解析 `status`、`run_id`、`force_notify`、`reason`、`gap_seconds`。若 `status=busy`，表示上一輪租約仍有效，本輪立即停止，不擷取、不分析、不送 Telegram；不得以第二個 run id 覆蓋。其他失敗則不得虛構 run id，並採 fail-safe 回報監控不可用。
3. 只產生一次原分析。force notify 只提升通知決策，不改寫盤勢；恢復輪在時間欄註明「監控已恢復」。
4. 第一次執行、無前次成功紀錄、距前次成功嚴格超過 180 秒，或前次恢復通知未送達時可強制通知；剛好 180 秒不算超過。
5. 不補跑關機期間每分鐘歷史分析，只重建當前狀態。
6. 恢復輪只有 bridge `sent` 或 `duplicate` 才把 `resume_delivered` 設 true；其他一律 false。
7. 完成後如有有效 run id，執行：
   `python -m trade_monitor.resume_guard complete --run-id <run_id> --resume-delivered <true|false>`
8. 恢復未送達時下一輪繼續強制通知；同一輪不得重送或重算。
9. resume guard 不得保存 message、Token、Chat ID 或個人財務資訊。

6. 快速模式不得省略收盤確認、樞紐狀態、防線資格、完整分析 JSON、交易憲法或禁止條件；只有 `DONT_NOTIFY` 的使用者可見訊息依 11.4 縮為固定短版。
7. 使用者明確要求啟動、恢復或繼續監控時，當下立即擷取圖表並回報完整快照，不等待下一個 heartbeat。
8. 每輪以實際喚醒後第一張畫面為基準，不依排程原定時間處理舊 K。
9. 此模式不能宣稱每分鐘準時執行或持續追蹤未收盤 K。

## 16. 結構化 adapter 固定介面

本節只負責時間、格式及傳輸，不改變交易規則：

1. begin 後立即擷取一張純圖表畫面，保存到：
   `D:\code\stock_ai_bot\.runtime\trade_monitor\captures\`
   取得原始位元組後立即記錄含時區 ISO 8601 `captured_at`。
2. 執行：
   `python -m trade_monitor.analysis_adapter prepare --image <圖片絕對路徑> --captured-at <captured_at>`
3. `context.expected_latest_closed_k_iso` 與 `expected_latest_closed_k_hhmm` 是本輪唯一權威最新已收盤 K 時間；`current_unclosed_k_hhmm` 只能標示未收盤觀察。

   - `market_state`：時段、號盤、象限、波動與必要位置資訊。
   - `pattern_observation.details`：四種型態、S／S／T／V 品質，以及必要的 Type 1／2／3 與左左／左右／右左／右右成熟度；不得把左右成熟度寫成第五種型態。
   - `single_contract_management_or_prohibition`：持倉、交易次數、冷卻與憲法禁止。
   - `constitution_event`：只供 adapter 更新內部持久狀態，不渲染為第十欄。每輪必須提供且欄位固定如下：

     ```json
     {
       "event_type": "NONE|SIM_ENTER|SIM_STOP|SIM_EXIT|COOLDOWN_REQUALIFIED",
       "event_id": "同一事件重跑時完全相同的穩定識別",
       "setup_id": null,
       "position_id": null,
       "direction": null,
       "entry_price_estimate": null,
       "stop_price_estimate": null,
       "risk_points": null,
       "latest_closed_bar_time": "逐字使用 context.expected_latest_closed_k_iso",
       "reason": "事件理由"
     }
     ```

   - 無持久狀態異動時用 `NONE`。`SIM_ENTER` 必須填 `setup_id`、`position_id`、`LONG|SHORT`、圖面估計進場、停損與正數風險點數；`SIM_STOP`／`SIM_EXIT` 必須填與現有模擬持倉相同的 `position_id`；其餘不適用欄位使用 null。不得把「條件式候選」或尚未成交的「可評估進場」誤記成 `SIM_ENTER`。
   - `event_id` 應由事件類型、權威已收盤 K、setup 與 position 識別組成穩定文字；同一事件重跑不得換 ID。adapter 會再計算雜湊去重並檢查合法狀態轉換。
   - `market_structure_state`：不渲染成通知欄位的完整結構快照。每輪必須使用 `version=3`，逐字使用 `context.expected_latest_closed_k_iso` 作為 `as_of`，並保存：
     - 一級與二級樞紐的穩定 `pivot_id`、高低種類、候選／局部成立／配對確認／失效／取代狀態、樞紐 K 時間、圖面估計價、首次看見時間、首次局部確認時間、首次配對確認時間、終止時間與比例品質。
     - `defense_lines` 同時保存小級多頭、小級空頭、大級多頭與大級空頭防線；`provisional_invalidation_boundaries` 同時保存多／空暫代邊界。ACTIVE 防線不得無事件消失，已配對樞紐不得在同時段消失。
     - 大小道氏狀態、Type 1／2／3 與左左／左右／右左／右右成熟度。
     - `scenario_context` 保存波段階段、所在位置、級數一致性、守住／受阻與突破／跌破兩條情境，以及當前四型態 setup 的 FORMING／ARMED／積極確認／保守確認／失效／不追價階段。
     - `anchor_context` 保存錨的完整歷史、作用中大小錨、控制級數、大小關係、趨勢／波動動態、工作象限與候選排序。新錨的 `first_seen_at` 必須是本輪或更晚的實際首次看見時間；不得把過去 K 的 `start_bar_time` 誤當首次看見時間。
     - setup 的觀察區、觸發區、失效區與最近障礙區都必須提供可靠性與原因；無法估計時價格使用 null、可靠性使用 UNAVAILABLE 並寫原因，不得默默刪除。相同 setup 的首次看見與階段首次改變時間不可回填。
     - 同一時段不得改寫既有 `pivot_id`、樞紐 K 時間或首次確認時間；新樞紐不得回填成上一輪已知。候選被更極端點取代時，舊點必須先標 `REPLACED` 並記錄 `replaced_by`。
     - 日盤與夜盤使用不同 `session_key`；新時段可重設序列。純截圖無法可靠估價時 `price_estimate` 使用 null，不得為了通過 schema 杜撰數字。
   - adapter 會驗證結構快照及相鄰兩輪轉移；防線、左右成熟度、候選階段或候選點位區域有實質變化時，即使模型誤給 DONT_NOTIFY，也由 adapter 強制升級為完整 NOTIFY。只有整份分析通過後才以檔案鎖及原子取代寫入 `analysis_state.json`。狀態損壞、倒退、同根 K 改寫或非法跳級時 fail-safe，該輪不採用方向、價位或持倉異動。
6. `original_decision` 完全依通知規則，只能 `NOTIFY` 或 `DONT_NOTIFY`。
7. 將完整 JSON 以無 BOM UTF-8 stdin 傳入：
   `python -m trade_monitor.analysis_adapter finalize --context-id <context_id> --force-notify <true|false> --run-id <run_id>`
   無有效 run id 時省略該參數。PowerShell 必須設定 InputEncoding、OutputEncoding、`$OutputEncoding` 為無 BOM UTF-8，並設 `PYTHONUTF8=1`。
8. `requires_analysis=false` 時不得再做圖面交易分析，以空 stdin 呼叫 finalize；SAME_BAR 且非 force notify 時保持安靜。
9. finalize 是唯一格式、樞紐／交易憲法持久狀態、完整／短版訊息及傳輸出口，負責驗證 JSON、驗證並原子保存 `market_structure_state`、以去重事件更新交易憲法狀態、force notify、event id、最多一次 bridge 及有效 run id 的 complete。finalize 後不得再呼叫 bridge、complete、重算 event id、直接寫狀態或改寫 message。
10. Codex 只顯示 finalize 原樣 message。Telegram failure 只可在對話附加既有失敗文字。
11. prepare／finalize 失敗、圖片遺失或 schema 驗證失敗時 fail-safe：不沿用未驗證方向、價位或訊號，不第二次呼叫 bridge；有有效 run id 而 finalize 未完成時，才直接 complete 並用 `resume_delivered=false`。
12. 截圖只供本機本輪分析，不上傳額外第三方；不得讀取或保存個人財務資訊。

## 17. 執行期 fail-safe 與相容性

- 本正式版 schema 版本為 `trade-monitor-analysis-v5`，`market_structure_state.version=3`；固定九欄文字順序不變，`constitution_event`、四向防線、`scenario_context` 與 `anchor_context` 都是內部欄位，不得顯示成第十個章節。
- 從 v1.6／state v2 升級時，prepare 只把既有 v2 快照在記憶中因果升級成空的 v3 `anchor_context`；只有整份 v5 分析通過後才原子寫入 v3。若驗證失敗，保留原有 v2 狀態並 fail-safe，不得寫入半份定錨資料。
- v1 結構狀態以因果方式遷移至 v2：既有單一防線依方向放入對應槽位，其他槽位保持 null；不得杜撰另一方向防線或回填情境時間。
- 樞紐、防線、反轉類型、左右成熟度與情境的使用者可見摘要仍寫入既有 details；完整跨分鐘生命週期只保存於 `market_structure_state`。
- prepare 的 `constitution_state.ok=false`、`trading_locked=true`、finalize 回報狀態事件不合法，或任何狀態檔損壞時，該輪不得新增、停止或退出模擬持倉；以資料不可用通知收斂，不得沿用模型記憶猜測額度。
- 相同 constitution event 在狀態已寫入後，即使程序於 Telegram 前中斷，重跑只會得到 duplicate；相同 canonical event id 仍由 bridge 去重。不得改 event id 規避去重。
- resume guard 的有效租約禁止重疊回合；租約逾時接手時強制恢復通知。舊 run id 的完成動作不得清除新 run 狀態。
- 根目錄 `trade_monitor_analysis_adapter.py`、`trade_monitor_bridge.py`、`trade_monitor_resume_guard.py` 與舊 schema 僅供回復相容；本正式版一律使用 `trade_monitor.*` 套件與 v5 schema。
- Telegram `trade_monitor_send_quiet_status`、聊天室、Bot、RRULE、target task 及通知政策不是交易規則；本版本不得自行更改其設定。

本規則僅作技術分析監控與系統研究，不保證獲利。期貨具槓桿與跳空風險，正式交易前仍須進行歷史、樣本外、模擬及小風險前向驗證。
