## 修改規則

1. 移除 OpenAI 的背景 70%／手動 20%／緩衝 10% 及歷史贈額總量、到期日派送限制。排程與手動共用實際帳戶，沒有保證保留手動額度。
2. 已設定金鑰依第二帳戶、第一帳戶順序選用；只有 HTTP 402／429 且錯誤碼為 `credit_balance_exhausted` 或 `insufficient_quota`，才視為明確額度拒絕並換帳戶。供應商用量上限不足不等於已查得免費贈額為零。
3. 兩個帳戶明確不足，才按既有規則檢查 DeepSeek。沒有金鑰、單次上限受阻亦沿用原備援規則，但訊息各自標明原因，不冒充額度耗盡。
4. 逾時、斷線、408／409、5xx、回應／用量不明不重送，未知費用仍預留；一般 429、401／403 不換帳戶或模型。即使錯誤正文帶額度字樣，也不能把 5xx 或權限錯誤當成明確額度拒絕。
5. 保留原子預留、跨帳戶單次上限、固定開發輪次／案例上限、用途與原始回應。新增帳戶歸屬表只記來源身分，不創造假贈額；舊贈額與舊請求不得歸零或改寫。
6. 人工／安全停止在選帳及備援之前生效；已確認的額度拒絕結算與帳戶封鎖在同一交易完成，不得以耗盡標記覆寫更強的人工停止。
7. 明確耗盡封鎖跨工作保留，不以新工作、換模型、重啟或修改贈額日期自動清掉；後續充值後解除需另外確認。本次沒有清除任何正式帳戶封鎖。

API 成功只證明請求可用，不保證使用免費贈額。若平台開放付費，可能有實際帳單；不自動儲值，也不修改平台付款設定。DeepSeek 原月額、用途分額及單次上限不在本次取消範圍。Luna／Terra 模型、提示詞、核心資料、評分、0050 與交易／回測規則不改。
